# 头部控制窗口设计方案

本文保留设计稿与实现规格。专用原生头部窗口现已实现，实际接口及使用方式见 `HEAD_UI.md`。最新设计稿：`head-ui-concept-v2.png`，使用内置 imagegen 工具，参考用户的部件草图与 Ground Slide 彩虹灯示意图；初版保留为 `head-ui-concept.png`。它是视觉概念稿，不是运行中的客户端截图，也不能整张当作按钮贴图直接使用。

## 布局与风格

保持用户草图的背面操作视角：上部两侧 Air、上部中央 Ground Slide；中部轨道与播放控件；底部左侧 Music、中间 CHUNITHM、右侧 Player。世界正面摆放的左右关系与窗口背面观察视角相反，这里不互换 Music 和 Player。

Minecraft 风格：方角、2～3 像素高光/阴影斜边、原版容器风格浅灰背景（约 #C6C6C6），中灰模块凹槽，浅底使用深色文字。文字使用游戏字体，图标使用独立像素贴图。色光主要沿边框、接口和输入区域显示，避免大面积持续闪烁。连接路径为直角细线，线不能穿过模块或控件。

布局建议以 432×288 逻辑像素设计，居中显示；适配窗口和 GUI 缩放时统一计算缩放及鼠标逆变换，保持像素网格和完整交互区域。下表坐标相对窗口左上角：

| 元素 | X/Y | 宽/高 | 内容 |
| --- | --- | --- | --- |
| 标题栏 | 8/8 | 416/20 | 头部控制、关闭图标 |
| 左 Air | 16/36 | 48/60 | 绿色上抬/下压示意与响应段 |
| Ground Slide | 88/36 | 256/60 | 标签、16 段触摸灯 |
| 右 Air | 368/36 | 48/60 | 同左 Air，独立状态 |
| Track | 156/108 | 120/62 | 仅标题和三个图标播放按钮，无轨道分格 |
| Music | 16/212 | 104/56 | 紫色唱片图标、连接状态 |
| CHUNITHM | 164/224 | 104/36 | 金色头部图标与总状态 |
| Player | 312/212 | 104/56 | 黄色头像图标、连接状态 |

新版已删除整排 OFFLINE / READY / INPUT 状态对照、底部说明和时间滑条；不保留底部说明区域。关闭按钮、刷新按钮、详细状态说明放在标题栏/悬停提示中，避免重复面板。

## 连接与响应是两个维度

不能仅用一个“亮/不亮”同时表示连接和按下。每个模块有可用性状态和输入响应值，连接路径显示可用性，模块内灯显示响应。

| 状态 | 外观 | 交互 |
| --- | --- | --- |
| 未连接 | 灰暗边框、灰图标、连接线熄灭 | 禁用，悬停说明缺少哪个接口 |
| 区块未加载 | 灰色，附小沙漏/省略符号 | 禁用，不强制加载区块 |
| 结构损坏 | 灰色，附红色断口标记 | 禁用，提示损坏部件 |
| 已连接、空闲 | 对应颜色的低亮边缘、完整连接线 | 模块可点击 |
| 正在响应 | 对应颜色高亮内灯与边缘，短暂余辉 | 保持可点击 |

不要只靠颜色传达状态；应同时显示图标/短标签，并提供键盘焦点、读屏名称和禁用原因。暂停时允许硬件输入测试继续显示，不把“暂停播放”误认为“输入设备断开”。

## 各模块颜色与行为

- **Air 左/右**：绿色。收到真实输入时亮起，左右独立；上抬/下压可点亮不同的像素箭头。无输入时仅保留低亮绿边。当前没有 Air 硬件或独立部件接口，先预留状态提供器，默认灰色；不能因轨道连接就伪造 Air 已连接。
- **Ground Slide**：16 个逻辑输入分区。左到右为红、橙、黄、绿、青、蓝、紫、粉的色谱；只有触发的分区高亮，松开后约 100～150ms 消退。可显示低亮色谱底色；设计稿中全部高亮只是演示。它与世界中的轨道是不同对象，未接入触摸设备提供器时应灰色。
- **Music**：紫色。歌曲面板接通后有点击反馈，但按最新要求暂不执行动作、不打开设置。不能把是否有音频能量误用为连接状态。
- **Player**：黄色。玩家面板接通后有点击反馈，但按最新要求暂不执行动作、不打开资料列表。
- **CHUNITHM**：当前头部，金色。点击查看/刷新五个结构接口的详细状态。不是第二套播放按钮。
- **Track**：紧凑的控制模块，只容纳开始、暂停、结束三个图标按钮与适当留白，不再显示八格轨道、分隔线或轨道预览。世界轨道的 16 条半格小轨道设置不变。连接正常时显示低亮边，断开时整体灰暗。

已连接模块的点击响应与真实输入响应分别来自 UI 操作事件和输入提供器。未连接模块不执行动作，但仍可显示悬停禁用说明。

## 播放控制必须是实际 UI 图标按钮

在轨道区域中放三个独立的可交互像素按钮，每个至少 24×24 逻辑像素，建议 28×28、间隔 6。按钮的常态、悬停、按下、选中、禁用采用不同图层，不用文字或聊天消息代替。

| 图标 | 操作 | 可用条件/行为 |
| --- | --- | --- |
| 绿色圆点 | 开始/继续 | STOPPED/FINISHED 时从头开始，PAUSED 时从当前位置继续；PLAYING 时不可重复开始，无谱面时置灰 |
| Ⅱ | 暂停 | 无谱面时仍可按，后端进行幂等暂停 |
| 红色方块 | 结束 | 无谱面时仍可按，后端进行幂等停止和清理 |

原“跳过”按钮按最新要求改为“结束”，操作为 STOP；后续如需快进或切下一首，应分别增加 seek/queue 接口。

播放按钮不随 Air/触摸输入闪烁。绿色圆点、白色双竖线、红色方块分别表示开始、暂停、结束；深灰代表禁用，金色细边代表当前播放/暂停状态。悬停提示给出动作名称和禁用原因。开始后不能重复启动播放实例。浅灰面板标题不使用文字阴影，以免产生重影。

启用开始键需要：头部、轨道、歌曲面板完整连接、管理员权限、已选择可用谱面且后端就绪。暂停和结束只依赖轨道及权限，无谱面时依然可按；默认后端为空时请求安全无操作。未准备好时不伪造播放状态。

当前设计不显示时间进度条或拖动控件；后续如增加 seek，应单独规划，不占用现在的紧凑 Track 按钮区域。

## 后续程序接口

下列是设计接口，不代表当前已提供这些类或方法。

```java
record HeadUiSnapshot(
    ConnectionSnapshot connections,
    AirState leftAir, AirState rightAir,
    GroundState ground, // exactly 16 response levels, each 0..1
    PlaybackState playback,
    long elapsedMs, long durationMs,
    boolean canStart, boolean canPause, boolean canSkip) {}

interface InputStatusProvider {
    InputSnapshot snapshot(HeadIdentity head);
}

interface PlaybackController {
    PlaybackSnapshot snapshot(HeadIdentity head);
    ActionResult startOrResume(HeadIdentity head);
    ActionResult pause(HeadIdentity head);
    ActionResult skipToEnd(HeadIdentity head);
}
```

复用已实现的 `PartConnections` 作为结构连接来源，复用 `PanelServices` 的玩家/歌曲提供器。Air 和 Ground Slide 的输入连接由新增提供器独立报告，不伪装成现有五个结构连接口。

头部应由“维度 + 头部原点 + 朝向”标识，所有操作提交给服务器。客户端提交动作，不提交任意音符位置或播放时间；服务器重新检查距离、权限、结构、会话及动作是否合法，再返回状态。UI 使用快照插值做灯光余辉，最终播放状态以服务器为准。画面在关闭后停止订阅，重新打开恢复真实状态。

输入响应属于实时状态，不写存档；歌曲选择、速度、镜像和导入资料属于配置，沿用已有世界持久化。播放实例按头部区分，避免一台机器暂停另一台。

## 分阶段落地与验收

1. 新增客户端 Screen 和独立 UI 资源，替换头部的容器列表；先接现有结构状态与 Music/Player 配置入口。Air/Ground 保持禁用占位。
2. 加入输入提供器与测试实现，验证左右 Air 独立发光、16 段只亮触发区域、断开后即时置灰。
3. 接入播放控制器，验证图标按钮的开始、暂停、继续和结束；未就绪时禁用，重复点击不会创建多份播放。
4. 验证关闭重开、世界重载、多人操作、结构破坏、区块卸载，以及不同 GUI 缩放/分辨率。鼠标与键盘焦点必须对应同一控件区域。

正式实现时按这些规则逐项验证，不以概念图中的亮灯状态作为实际连接事实。
