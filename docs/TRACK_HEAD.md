# 独立轨道头部

空地执行 `/chunithm head`，需要管理员命令权限。命令会从执行位置向 -X 偏移 1 格后向 +X 生成宽 11 格、向上高 4 格、沿 Z 厚 1 格的头部，替换这个范围的 44 个方块。正面朝 +Z；从南侧面向北看正面。生成前检查完整区域已加载且位于世界边界内。

- 主面板：宽 11、高 3、厚 1。
- 下方延伸底座：宽 11、高 1、厚 1，与主面板共用连续金色背景。
- 进度条：边框外沿宽 8 格，两侧留白各 1.5 格；黑色内部宽 7.875 格。
- 顶部黑色计数板四等分，每栏宽 2.75 格，高 0.875 格（比原先增加 0.5 格），仅显示四个居中的数字，保留黄、橙、绿、灰配色，字号为初版的 3.2 倍（四倍版本的 80%）。
- 分数、连击、进度条和 10 个完成度小格由数据接口更新；不计算评分或连击规则。

示例：若轨道起始方块位于 0,-61,0，头部可独立放在它后方：

```mcfunction
/execute positioned 0 -61 -1 run chunithm head
```

这样底座从轨道底面开始，正面朝轨道，头部向轨道两侧各延伸 1 格，宽 11 格。`/chunithm track` 和运动测试不会自动生成头部。

模型为 44 个原生方块资源组成的面板，碰撞体与外形一致。正面 1408×512 贴图按每格 128×128 分片，确保数字标签跨块接缝连续；方块 ID 为 `head_列_行`，行 0 为底座。暂不提供零散部件的创造模式物品，使用整体生成命令。

贴图和资源重建：`powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\generate-head.ps1`。正面预览见 `head-preview.png`。此脚本单独运行，不包含在现有音符资源生成器内。

MAX COMBO/SCORE 区域高 0.9296875 格，比原先增加 0.5 格，标签和数字名义字号为 45 像素（原来的 1.5 倍），使用粗体，按实际字形包围框垂直居中。顶部计数区同样加高 0.5 格。厚度与一格高底座不变。左右侧为紫色，背面为黑色。旧头部建议在同一锚点重新执行生成命令以更新所有部件。

## 显示数据接口

Java 接口：`TrackHeadDisplay.update(ServerLevel level, BlockPos origin, HeadDisplayData data)`。origin 是头部最左下方块位置（比 head 命令的执行锚点向 -X 偏一格）。数据依次为 critical、justice、attack、miss、maxCombo、score，均须非负。完成度自动按 score / 1,010,000 × 100% 计算，不再接收百分数；超过满分时图形封顶 100%，分数字段仍显示实际值。

在生成头部的同一个锚点执行测试命令（可用 execute positioned 固定坐标）：

```mcfunction
/chunithm head
/chunithm head_data 1717 11 1 0 1729 434300
```

输入分数 434,300 对应 43%，会显示 4 个完整小格、30% 长条。每 10% 填满一格，第 1～3 格始终蓝色，第 4～10 格金色；输入小于 30% 时长条为蓝色，达到 30% 后处于第四格阶段，长条改为金色。10%、20% 等整数十位时长条归零；100% 为十格全满、长条归零。前三格尺寸小于后七格，CLEAR 居中放在第四格与进度条之间。

顶部四个计数不显示类型文字；MAX COMBO 与 SCORE 的数字中心在进度条外沿的 3/8 和 7/8 点，按从头部左下角计算整体右移 0.25 格后分别为 x=4.75、8.75。图形采用原版 text_display / block_display，背景贴图不含固定数字。更新仅替换该头部正面的带标签显示实体，当前刷新方式为重建显示层；不包含实时评分、计时和网络专用协议。显示实体可随世界保存，源数据对象需要业务层自行持有。

重新进入客户端并在原锚点执行 `/chunithm head` 更新旧背景，再执行 head_data 查看数据。代码与百分比边界检查通过，尚未完成本轮游戏内视觉复测。
方框使用剪切变换形成平行四边形，边框和内部填充倾斜一致。所有进度条和方框（包括空格）与数字一样使用 Brightness(15,15)，在暗处保持满亮度；此效果不等于光影模组的泛光。第二行标签和数字整体右移 0.25 格。整数运算拆分满格与剩余进度，避免十分位边界的浮点误差。计数、分数和进度测试通过；尚未进行本轮游戏内视觉复测。

## 当前生成锚点（替代早期固定 +X/+Z 说明）

站立方块 = floor(执行位置) 再向下 1 格。头部的中间最下方块位于站立方块沿玩家水平朝向前进 1 格的位置，左右各延伸 5 格，向上共 4 格，正面朝向玩家。头部显示数据命令需在同一位置、同一朝向执行。通过 execute positioned/rotated 可指定锚点与朝向；更新 Java 接口现使用 Placement 而非单个原点。

轨道起点行的正中方块就是站立方块，左右各延伸 4 格，长度从这一行沿玩家水平朝向向前计算。判定线和音符运动随轨道旋转。头部与轨道仍独立生成。
