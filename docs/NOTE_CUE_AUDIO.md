# 判定线节拍提示音

选中谱面并开始播放后，每个 Tap（含 EX-Tap）、Hold 首尾、Slide 整条路径的首尾、Air、Flick 到达判定线时，左右 Air Sensor 同时播放一次相同提示音。Air Action 的实际动作首尾同样触发；Slide 中间控制点、长条持续判定、装饰线、拍线和变速提示线不触发。相同时间的音符只播放一次，避免和弦叠加音量。

提示音使用从 `chu.acb` 提取的 `SE_TOUCH_TAP_CRITICAL` 音源（Cue 59，Waveform 50，内置 AWB ID 286）。原始解码 WAV 转为 44.1 kHz 单声道 Vorbis，未经过 MP3 二次转码；以保留音高的时间压缩将原始约 1.362 秒收缩至 0.200 秒，末尾加入 5 ms 淡出避免截断杂音，不循环。资源为 `assets/minecraftchunithm/sounds/note/tap_critical.ogg`，声音事件为 `minecraftchunithm:note.tap_critical`。使用这一段独立音源，不叠加 Cue 中其他音色或持续音层。修改音量使用 Minecraft 的“方块”与总音量设置，歌曲仍使用“唱片机/音符盒”类别。

每侧只保留一个声音实例。新提示到来时先停止两侧旧实例，再从开头同时播放新实例；没有尾音排队或叠加。每侧音量 0.2（20%），空间衰减范围 64 格。声源固定在相应 Air Sensor 内侧面五个感应孔的中孔处，随机台建造朝向旋转；谱面镜像不交换声源。服务端校验 Head → Track → Ground Slide → Air 的实际连接；某侧断开后该侧停止发声，上游断开后两侧停止发声。

触发使用谱面原始毫秒时间，与音符中心到达 `RhythmTiming.judgment(length)` 一致，不使用轨道末端坐标，也不按屏幕位置反复触发。SPEED、镜像和视觉变速不改变提示时刻。服务端每 5 tick 同步播放时钟、播放修订号与连接状态；音符时间列表按 4096 条分包，每个会话对每位玩家仅发送一次。客户端每个游戏 tick 和画面提取帧检查到达事件，以避免把密集音符固定量化为 50 ms。时钟小幅回退不会重播旧事件；一次卡顿跨过多个事件时只保留最新事件，不在恢复后爆发补播。

暂停、停止、seek、切谱、轨道卸载、退出世界均清理当前提示。恢复和 seek 从当前位置之后继续，停止后重新开始则重新允许第一个音符。无歌曲音频的测试谱面也能独立发出提示。提示与乐曲共用服务端谱面时间；仍受网络、服务器 tick、客户端帧率与音频设备缓冲影响，并非设备采样时钟驱动的判定系统，也不代表玩家命中或参与计分。

重新生成音频（先运行音符音源提取脚本）：

```powershell
python tools/import-note-cue.py
```

验证：`./dev.ps1 build` 检查所有类型首尾、同刻合并、密集事件替换、跳转/恢复/重启和四朝向发声位置；`./dev.ps1 runClient -PinputQuickPlay -PnoteCueQuickPlay` 使用独立的 `build/air-input-test` 世界检查原生双声源、打断、传输控制、以及与 ID 103 乐曲同时播放，结束后自动关闭客户端。
