# 轨道边框双声道播放

已导入曲目使用 `song.json` 的 `audio.soundEvent`、`audio.resource`、`durationMs`、`offsetMs` 接入谱面播放。玩家站在 Ground Slide、面向头部时，左侧边框播放原音频的左声道，右侧播放右声道。四个建造朝向采用同一规则；谱面镜像不交换音乐声道。视角转动时，原版声音引擎按世界中的声源方位定位。

每侧只有一个原版定位声音实例，发声点取该边框上离听者最近的位置，纵向限制在轨道起点与末端之间，高度为轨道边框顶面 0.75 格。本地 X=0.25 / 8.75 分别对应玩家左 / 右。沿边框走动仍能就近听见音乐，避免沿线同时播放多个副本产生叠音。音量遵循原版“唱片机/音符盒”类别和总音量。

客户端在后台解码当前歌曲的原始 Vorbis 文件，缓存一份 16-bit PCM。读取时按样本帧拆为左右两个单声道流，交给 Fabric `SoundInstance.getAudioStream` 与原版声音引擎播放；没有重新编码、合并声道或改动已导入的音频资源。单声道来源则两侧读取相同声道。两边使用相同的起始样本帧。

服务端以谱面时间为准同步，不依赖控制窗口是否打开。预滚期间不发声；开始、暂停、恢复、停止、seek、切歌、轨道卸载/损坏与退出世界均有对应处理。暂停停止当前声音实例；恢复从缓存中的准确样本帧建立新实例。时间跳转也不会从歌曲开头重新播放。谱面 SPEED 仅影响视觉流速，不改变音乐音高与速度；SFL 视觉停止不暂停音乐。音乐完整尾音纳入会话结束时间。

同步快照每 5 个游戏 tick 更新，客户端在快照之间按本地时钟推进。差异超过 200ms 时重新定位。当前是原版定位声源的首版同步，仍可能受到服务器 tick 波动、网络与音频设备缓冲延迟影响，不是音频设备采样时钟驱动的判定系统。尚不实现音符评分。

验证包括：四朝向玩家左右、最近点与端点限制；原始 PCM 与左右流逐字节比对、非零样本偏移；独立测试世界中两个原生单声道流实际启用、暂停、恢复、跳转至 60 秒与停止。

音符经过判定线时的节拍提示由两侧 Air Sensor 同时发声，使用独立的单声道音源和“方块”音量类别，详细规则见 [NOTE_CUE_AUDIO.md](NOTE_CUE_AUDIO.md)。
